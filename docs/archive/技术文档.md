## 一、项目概述

### 1.1 核心目标

构建50个三线城市导航站 + 1个导航总站，实现月入3-10万元被动收入。

### 1.2 核心优势

| 维度 | 本项目 | 其他互联网项目 |
|------|--------|----------------|
| 启动成本 | 0元（无域名、无服务器、无广告） | 几千到几十万不等 |
| 技术门槛 | 零代码（复制粘贴指令） | 需要编程、设计、运营能力 |
| 时间投入 | 累计1周做完所有网站，每天15分钟维护 | 每天8小时以上 |
| 风险 | 几乎为零（一个站不影响其他站） | 极高（99%失败） |
| 收入稳定性 | 随时间递增，越老越值钱 | 波动极大，随时可能消失 |
| 可复制性 | 100%标准化复制 | 几乎不可复制 |

### 1.3 三层金字塔架构

```
第三层：导航中的导航（总站）- 流量入口+导航站收录变现
    ↓ ↑ 互相导流
第二层：50个三线城市便民导航站 - 核心盈利单元
    ↓ ↑ 互相导流
第一层：不良资产导航站（已跑通）- 原型验证
```

## 二、盈利模型

### 2.1 核心盈利公式

**单站日收入 = 日均IP × 1.5（页面浏览量）× 2（广告位）× 10元/千次展示 ÷ 1000**

- 日入20元 = 日均667个IP（三线城市3个月自然达成）
- 50个站月收入 = 50 × 20元/天 × 30天 = **3万元/月（仅广告）**
- 加上商家收录和置顶广告，实际收入可达**5-10万元/月**

### 2.2 变现方式（按优先级排序）

| 优先级 | 变现方式 | 收费标准 | 预期收益 |
|--------|----------|----------|----------|
| 第一优先级 | 百度联盟广告 | 每千次展示10元 | 日均700IP=日入20元 |
| 第二优先级 | 商家付费收录 | 300元/年 | 50个站年收入22.5万元 |
| 第三优先级 | 分类置顶广告 | 500元/月/分类 | 50个站月收入5万元 |
| 第四优先级 | 总站专属变现 | 200-2000元/月 | 面向全网导航站站长 |

## 三、技术架构

### 3.1 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| AI编程 | Trae（SOLO模式）、DeepSeek、豆包 | 代码生成 |
| 托管平台 | Netlify免费版 | 无限站点、自动HTTPS、全球CDN |
| 变现平台 | 百度联盟 | 所有网站共用一个账号 |
| 管理工具 | Excel | 统一管理所有网站数据 |

### 3.2 Netlify免费版限制与解决方案

| 限制项 | 免费版额度 | 解决方案 |
|--------|------------|----------|
| 每月带宽 | 100GB | 超过后将流量最大的2-3个站迁移到Cloudflare Pages |
| 每月构建时间 | 300分钟 | 使用拖拽部署，不占用构建时间 |
| 团队成员 | 1人 | 完全足够 |

### 3.3 技术规范

- **架构**：纯静态HTML网站，不需要数据库和后端
- **设计**：响应式设计，完美适配电脑、手机、平板
- **性能**：页面大小不超过100KB，加载速度极快
- **一致性**：所有网站从同一个母版生成，100%一致

## 四、项目结构

### 4.1 目录结构

```
navigation-matrix-v3/
├── 01-master-template/     # 唯一的源代码母版（所有修改只在这里做）
├── 02-city-sites/          # 50个城市站（自动生成，绝不手动修改）
├── 03-master-navigation/   # 导航中的导航总站
├── 04-deployed/           # 已部署到Netlify的网站备份
├── 05-assets/             # 通用资源（logo、图标等）
└── 06-backups/            # 每日自动备份
```

### 4.2 开发铁律

1. 永远不要直接修改 `02-city-sites/` 里的任何文件
2. 所有功能、样式、内容修改，**只在 `01-master-template/` 里做**
3. 修改完成后，让AI一键重新生成所有50个城市站

### 4.3 网站文件结构

每个城市站包含以下文件：

```
city-name/
├── index.html      # 主页面
├── style.css       # 样式文件
├── script.js       # 脚本文件
└── config.json     # 配置文件（城市名称、拼音、链接数据）
```

### 6.2 第一步：生成通用母版

**母版设计要求：**

1. 极简风格，白色背景，黑色文字，蓝色链接(#0066cc)
2. 响应式设计，完美适配电脑、手机、平板
3. 加载速度极快，页面大小不超过100KB
4. 没有任何多余的动画和效果，只保留核心功能

**核心功能：**

1. 顶部搜索框，可以搜索所有链接名称
2. 分类导航，点击分类标题可以展开/收起该分类下的链接
3. 每个链接显示名称，点击后在新标签页打开
4. 底部版权信息和免责声明
5. 右下角固定位置的回到顶部按钮

**参数化要求：**

1. 所有出现城市名称的地方，全部使用全局变量 cityName
2. 所有出现城市拼音的地方，全部使用全局变量 cityPinyin
3. 所有导航链接、分类名称、紧急电话，全部提取到单独的 config.json 文件中

**母版验证标准：**

1. 修改config.json中的cityName为"邯郸"，整个网站所有文字自动更新
2. 点击分类可以正常展开/收起
3. 搜索框可以正常搜索链接
4. 回到顶部按钮功能正常
5. 调整浏览器窗口大小，手机端显示正常

### 6.3 第二步：批量生成50个城市站框架

基于通用母版，为每个城市生成独立的完整网站文件夹：
- 文件夹名称使用城市拼音
- 每个文件夹包含完整的4个文件：index.html, style.css, script.js, config.json
- 每个城市的 config.json 自动填入对应的 cityName 和 cityPinyin

### 6.4 第三步：批量收集官方链接

**收集要求：**

1. 只收录官方网站，绝对不要收录第三方网站
2. 确保所有链接都是可以正常访问的
3. 每个分类至少8个链接，最多12个
4. 紧急电话分类必须包含：110、120、119、122、95598、95158、12315、12345

### 6.5 第四步：批量部署到Netlify

**标准部署流程（3分钟/个网站）：**

1. 打开Netlify后台：https://app.netlify.com
2. 登录账号（用GitHub或邮箱注册）
3. 跳过初始设置，找到"Deploy manually"区域
4. 把城市文件夹直接拖到页面中间的拖拽区域
5. 部署完成后，点击"Site settings" > "Domain management" > "Edit site name"
6. 修改为 `城市拼音.netlify.app`
7. 重复以上步骤，部署所有50个网站
8. 把所有部署好的网站文件夹复制一份到 `04-deployed/` 目录下备份

### 6.6 第五步：制作并部署导航总站

**总站要求：**

1. 网站名称：导航百科
2. 网站描述：全网精选优质垂直导航站目录
3. 分类改为：
   - 行业垂直导航
   - 工具导航
   - 资源导航
   - 本地生活导航
   - 其他导航
4. 在"本地生活导航"分类下，添加50个城市的链接
5. 每个网站底部添加总站链接
